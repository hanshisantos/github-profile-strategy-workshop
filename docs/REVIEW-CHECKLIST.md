# Review before publishing

## Claims and evidence

- [ ] My introduction names a focus or direction a reader can understand.
- [ ] Every project claim matches work I actually did.
- [ ] My own contribution is distinct from the source project.
- [ ] Plans, proposals and untested changes are labeled.
- [ ] Project links lead to readable evidence, not only a list of tools.
- [ ] Any numbers, outcomes or credentials have a source I can verify.

## Public-content boundary

- [ ] I have permission to publish the code, screenshots and text.
- [ ] No passwords, tokens, API keys or private endpoints appear.
- [ ] No workplace code, internal deck, student record or private feedback appears.
- [ ] I have not included someone else's identity or quotation without permission.
- [ ] Screenshots use fictional or deliberately public data.
- [ ] I understand that the profile repository must be public for the README exercise.

If a secret has been exposed, do not try to fix it only by deleting a line. Notify the resource owner and follow the applicable credential-revocation and incident process.

## Attribution and AI assistance

- [ ] The upstream project and its author are credited.
- [ ] Copied materials retain the required license and copyright notices.
- [ ] Citation links point to the source and version I used.
- [ ] My citation file names the correct authors, not all event participants.
- [ ] I disclosed AI assistance when required and checked its output.

## Profile experience

- [ ] My profile repository name exactly matches my username.
- [ ] Its root `README.md` is nonempty and merged into the default branch.
- [ ] The README appears on my public GitHub profile.
- [ ] Links and images work for the intended public audience.
- [ ] Headings and link text are readable on desktop and mobile.
- [ ] I removed all template placeholders.
- [ ] My pinned repositories support the direction in my introduction.

## Feedback and next action

- [ ] A partner can identify my direction and my contribution.
- [ ] I have one bounded question to ask a mentor or community.
- [ ] I chose one revision and a date to make it.

This checklist supports review. It is not a security audit, certification or proof that an application is production-ready.
